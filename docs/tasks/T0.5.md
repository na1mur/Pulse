| ID | Rule |
|---|---|
| R-10 | A **day** is a calendar date in a timezone, identified as `YYYY-MM-DD`. All day math uses one well-tested timezone library with the IANA database. Never use device-locale date strings. |
| R-11 | **Day attribution:** a session's seconds count toward the local days it covers, *clipped at local midnight* in the session's own timezone (R-09). A session that crosses midnight stays **one record** (D-03). History shows it as **one row per local day** with the same title, tag and summary: the first row ends at 23:59:59, the next starts at 00:00:00; editing either row edits the session. The current session timer keeps counting across midnight; only the day total resets. Devices that were offline at midnight need no special handling (US-5.4). |
| R-12 | **"Today", "this week", etc.** are evaluated in the user's **current timezone setting**, not the device's timezone. A period is a set of day keys; its total is the sum of the seconds attributed to those keys. |
| R-13 | **Week** = 7 consecutive days starting on the user's *week start* setting (default Monday). **Month** = calendar month in the user's timezone. **Year** = calendar year. Rolling windows exist only when labelled explicitly ("Last 7 days") (US-10.1). |
| R-14 | **Period IDs:** day `2026-10-24`, week = date of its first day `W2026-10-19`, month `2026-10`, year `2026`. |
| R-16 | Store instants, not accumulated numbers. Compute durations in **integer seconds**. Never accumulate floating-point minutes. |
| R-17 | **Worked time** (total time) of a day or period = attributed seconds of closed sessions + attributed seconds of the running session up to *now*. It is always live. The **current session timer** = now − start of the running session (0 when idle; it resets on every start). The **day total** = today's worked time; it never resets on pause, only at local midnight (US-5.1). |
| R-18 | **Display:** clocks show `H:MM:SS` (hours unbounded). Summaries show `Xh Ym`, **rounded down** to the whole minute, so a goal is never shown as reached before it is. Displayed elapsed time is never negative (clamp at 0). Credits display per R-44. |

Related: R-09 (a session records the timezone in effect when it was created), R-15 (the timezone setting changes only by explicit user action), D-03 (one record across midnight), D-19 (one shared fixture suite in `packages/contract/fixtures/`, both implementations pass it in CI).

### Interfaces

Fixture files (`packages/contract/fixtures/time/`), each `{ "description", "rules": ["R-.."], "cases": [{ "name", "input", "expected" }] }`. Instants in fixtures are ISO UTC strings with `Z` (some inputs with fractional seconds to prove truncation); day keys `YYYY-MM-DD`; week start `"monday"`..`"sunday"`.

| File | input | expected |
|---|---|---|
| `instant.json` | `{ instant }` | `{ epochSeconds }` (floor) |
| `duration.json` | `{ start, end }` | `{ seconds }` (clamped at 0) |
| `day-key.json` | `{ instant, timeZone }` | `{ day }` |
| `day-bounds.json` | `{ day, timeZone }` | `{ start, end, seconds }` |
| `period.json` | `{ kind: "day"\|"week"\|"month"\|"year", day, weekStart, timeZone }` | `{ id, firstDay, lastDay, start, end, seconds }` |
| `day-rows.json` | `{ startedAt, endedAt: string\|null, timeZone, now }` | `{ rows: [{ day, start, end, seconds, localStart, localEnd }] }` |
| `period-total.json` | `{ sessions: [{ startedAt, endedAt\|null, timeZone }], kind, day, weekStart, timeZone, now }` | `{ seconds }` |
| `display.json` | `{ seconds }` (may be negative) | `{ clock: "H:MM:SS", summary: { hours, minutes } }` |

Functions (same names in both languages, camelCase in TS, snake_case in Rust; idiomatic types allowed: Rust may use newtypes and `jiff::Timestamp`, TS uses `number` epoch seconds and `string` day keys):
- `parseInstant(iso) -> epochSeconds` (floor), `formatInstant(epochSeconds) -> iso Z`
- `durationSeconds(start, end) -> seconds` (>= 0)
- `dayKey(instant, timeZone) -> day`
- `dayBounds(day, timeZone) -> { start, end }`
- `period(kind, day, weekStart, timeZone) -> { id, firstDay, lastDay, start, end }`; `periodId(kind, day, weekStart) -> id`
- `dayRows(session { startedAt, endedAt | null, timeZone }, now) -> rows`
- `periodTotal(sessions, kind, day, weekStart, timeZone, now) -> seconds`
- `formatClock(seconds) -> "H:MM:SS"`, `summaryParts(seconds) -> { hours, minutes }`
- Errors: unknown timezone or malformed day/instant -> a typed error (Rust `thiserror` enum; TS a domain error class), never a panic or a silent default.

Clock: Rust `pub trait Clock: Send + Sync { fn now(&self) -> jiff::Timestamp; }` in `ports`; `SystemClock` in `adapters`; `FakeClock` (set, advance) under feature `test-support`. Server: `Clock` interface `{ now(): Temporal.Instant }` (or epoch ms; full precision, domain truncates) with a Nest provider token, `SystemClock`, and `FakeClock` for tests.

### Review focus
- Whole-second truncation on the way in, and half-open intervals: per-day rows must sum to the session total exactly; a session ending exactly at local midnight has no zero-second second row.
- DST: 23 h and 25 h days (Los Angeles 2026-03-08 / 2026-11-01, Auckland 2026-09-27 / 2026-04-05); a session spanning the repeated hour; a skipped midnight (America/Santiago 2026-09-06) where the day starts at 01:00.
- Non-whole-hour offsets (Asia/Kathmandu +05:45) and far-east days (Pacific/Auckland) where the UTC date differs from the local one.
- Week start on every weekday, weeks crossing month and year ends, leap day 2028-02-29.
- `periodTotal` with a session timezone different from the user's timezone (rows keyed in the session's zone, period keys in the user's).
- Running sessions clipped at `now`; `now` before the start; negative display input.
- Both runners fail on an unknown fixture file or case shape (no silent skip).
- Core: no clock reads in `domain`; `pulse-core` still builds without OS features; bundled tzdb size reported.
