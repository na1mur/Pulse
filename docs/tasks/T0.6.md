## Plan

### Slices

1. **Dev services and one-command scripts** - devops-engineer - `infra/docker-compose.dev.yml` (PostgreSQL with healthcheck and a named volume, Mailpit); root scripts `dev:up` (start services, wait for healthy, print URLs and the connection strings), `dev:down`, `dev:reset` (drops the volume); a `dev` doc section in the README or `docs/DEVELOPMENT.md` with the under-10-minutes path; `CLAUDE.md` Commands line; knowledge index entry. Tested: the compose file validates (`docker compose config`), the scripts have unit tests for their argument handling and output, and, once the daemon runs, `dev:up` then `dev:down` against a real Docker.
2. **Seed runner** - backend-engineer - `pnpm dev:seed` (`apps/server/scripts/seed.ts` or similar): connects with `DATABASE_URL` (default the dev database), applies `apps/server/seed/*.sql`/`*.ts` in name order, records applied seeds so a rerun is idempotent, refuses to run against a database that is not the dev one (host not local, or an explicit `NODE_ENV=production`). Tested with Vitest on the ordering, idempotency and refusal logic (injected database port); no schema needed.

### Interfaces

- Dev database URL: `postgres://pulse:pulse@localhost:5432/pulse` (dev-only credentials, bound to 127.0.0.1).
- Mail catcher: SMTP `localhost:1025` (no auth, no TLS), UI `http://localhost:8025`. Documented values for `SMTP_HOST`, `SMTP_PORT`.
- Root scripts: `dev:up`, `dev:down`, `dev:reset`, `dev:seed`. The server keeps `pnpm --filter @pulse/server dev`.
- Seed files: `apps/server/seed/NNN-name.sql` or `.ts`; applied seeds recorded in a `dev_seeds` table the runner creates itself.

### Review focus

- The dev compose file must not bind to non-loopback interfaces or contain anything a production deployment could pick up.
- Dev credentials never reach `infra/.env.example` as defaults for production (OPS-03 refuses weak secrets).
- Seed runner safety: it must never run against a non-dev database.
- `pnpm verify` and CI must stay Docker-free.
- Works on Windows (Git Bash and PowerShell) and Linux.

### Fix 1 - devops-engineer (host ports overridable)

Trigger (lead, verified): a local `postgres` (pid 6448) listens on 0.0.0.0:5432 and something holds 1025 on this machine, so fixed host ports would fail `dev:up` here and for any contributor with a local Postgres.

Changed: the compose host ports are `127.0.0.1:${PULSE_DEV_DB_PORT:-5432}`, `${PULSE_DEV_SMTP_PORT:-1025}`, `${PULSE_DEV_MAIL_UI_PORT:-8025}` (loopback kept, container ports fixed). `scripts/dev.mjs`: `resolvePorts` validates the three variables (whole number 1-65535, no two equal; exit 2 before any Docker call); the printed URLs follow the ports in use (default output byte-identical); the resolved ports are always passed to Compose; with a non-default database port `dev:up` tells the user to export `DATABASE_URL` before `dev:seed`. `up` checks the host ports before starting (`probePort`: connect, then try to listen, because 1025 has no listener but refuses one with `EACCES`), skips services already running, and fails naming each busy port and its variable. `scripts/dev.test.mjs` now has 34 tests; `docs/DEVELOPMENT.md` has a "Changing the ports" section and an updated Troubleshooting entry.

Run: `node --test scripts/dev.test.mjs` 34/34; ESLint and Prettier clean; `pnpm check --only docs` passed; bad values exit 2 with a message; the real `probePort` on this machine reports 5432 and 1025 busy, 8025 and 5433 free.

Not verified (daemon off): a real up, down and reset with overrides; `docker compose ps --services --status running` against a real daemon; the `EACCES` listen path in the suite (manual run only).

Open: whether `dev:seed` or the seed runner should read `PULSE_DEV_DB_PORT` itself (currently the user exports `DATABASE_URL`, as `dev:up` prints). Lead's call: deferred to the ledger. On this machine use `PULSE_DEV_DB_PORT=5433`.
