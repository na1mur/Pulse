### backend-engineer, fix round 1 (change-review, Spec axis)

1. **No personal data in logs (OPS-04).** New `platform/logging/safe-error.ts`: an error is logged as class name plus a code when it has a short upper-case one (PostgreSQL SQLSTATE, Node codes), and its stack as frames only (lines starting with "at "), never the message text. `ContractExceptionFilter` logs `Unhandled error: <class [code]>` with the frames; a thrown non-Error is described by its type only. `JsonLogger` applies the same to an Error message and drops the message lines of any stack passed to it, and `extraFields` is now an allow-list (`method`, `route`, `status`, `durationMs`). `describeStartupFailure` prints non-config failures the same way, except errors the server words itself with no driver text or values: `ConfigError`, `MigrationError` and the new `DatabaseUnreachableError` keep their message (so "Cannot reach the database at host:port" stays readable). Tests: an error whose message holds an email address, with a PostgreSQL code, thrown from a real handler: the email is in neither the response nor any log line (`request-logging.http.spec.ts`), plus `safe-error.spec.ts`, `json-logger.spec.ts`, `bootstrap.spec.ts`, and the two `app.http.spec.ts` cases that used to assert the thrown value was logged.
2. **One shutdown deadline.** New `platform/lifecycle` (`ShutdownDeadline`, global `LifecycleModule`). `GracefulShutdown` starts the deadline (`shutdownGraceMs`, 8 s in all) and drains HTTP for at most `shutdownHttpDrainMs` (6 s); `DatabaseShutdown` closes the pool within what is left. The comment in `app-config.ts` is corrected. Test: a stuck request holding a pool connection in `pg_sleep(60)`, budget 1000 ms (drain 600 ms): `close()` takes between 550 and 1500 ms; with the old two independent waits it took 1620 ms and the test failed (checked by reverting the pool step).
3. **Standard shape for errors Node answers itself.** New `platform/http/client-error.handler.ts`, installed by `configureApp`: on `clientError` it writes the contract's JSON body (code, message, requestId) with `Pulse-Request-Id`, `Pulse-Server-Time`, `Content-Length` and `Connection: close`, then closes; a socket that is not writable or already carries a partial answer is destroyed instead. Statuses follow the contract's code, not Node's: malformed request line and oversized header (Node would send 400 and 431) answer 400 `VALIDATION`; a request or headers timeout (Node 408) answers 503 `UNAVAILABLE`, because no contract code maps to 408 and the generated clients only know the contract's statuses. The sweep interval for those timeouts is now `min(5 s, limits)` instead of Node's 30 s default. Nothing the client sent is echoed or logged (one warning line with status and request ID). Tests over raw sockets in `client-error.http.spec.ts`: malformed request line, 100 kB header, a request that never completes (150 ms limits), a normal request afterwards, nothing echoed or logged, and unit cases for the unwritable and partially written sockets.

Verified: `node scripts/check.mjs --only ts --only docs` green (792 server tests).
