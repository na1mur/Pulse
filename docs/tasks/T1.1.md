Entities (spec section 6, verbatim invariants):

- **User**: id, email (unique, case-insensitive), email verified at?, password hash?, Google subject?, created/updated. A password hash or a Google link (or both).
- **EmailToken**: id, user, purpose (verify email / reset password / change email), token hash, new email?, expires, used at?. Single use; only hashes stored; verify 24 h, reset 1 h.
- **AccountPreferences**: user, timezone (IANA, null until confirmed, R-15), week start, count weekends, time format, theme, notification toggles, onboarding done?. One row per user.
- **Device**: id (generated on install), user, name, platform, app version, push token?, created, last seen.
- **Credential** (refresh token): id, device, user, token hash, family ID, issued, expires, revoked. Only hashes stored; reuse of a rotated token revokes the whole family.
- **Tag**: id, user, name, name key, category (productive / leisure / neutral), distraction class (gaming / social, leisure tags only)?, archived?, created/updated, deleted?. Unique (user, name key) among non-deleted tags.
- **ProcessedCommand**: user, command ID, result, created. Kept at least 30 days (R-34).
- **Revision**: user, current revision; every change record stores its revision (R-35).

Rules: R-34, R-35, D-20 (Kysely, raw SQL migrations), D-30 (credential ops are not commands; idempotency store never holds raw tokens). Appendix A limits: email <= 254, tokens <= 512, push token <= 4096, device name 1-100, app version 1-32, tag name 1-40, platform windows|android, time format system|12h|24h, theme system|light|dark, defaults week start Monday / count weekends on. Notification toggles per contract `NotificationToggles` (creditLow, creditZero, creditBelowZero, dailyGoal, weeklyMonthlyGoal, gameSuggestion). Contract entity shapes: `packages/contract/src/entities.ts`.

Context: `docs/ARCHITECTURE.md` section 3 (server layout: `platform/` holds database), `.claude/rules` NestJS/PostgreSQL rules (schema changes only through versioned migrations; invariants as constraints; integration tests on a real PostgreSQL), skills `postgresql-table-design`, `nestjs-best-practices`. Dev database: `pnpm dev:up` (postgres://pulse:pulse@localhost:5432/pulse). `pg` is already a dependency (move to `dependencies` stays); Kysely to be added. T1.2 owns validated config, so T1.1 reads `DATABASE_URL` minimally.

No open decisions block this task.

## Plan

### Slices
1. Migration runner (`platform/database`): versioned raw-SQL migrations with up and down, applied in order inside transactions, tracked in a table, advisory lock against concurrent starts; run on server start before listening. Test on real PostgreSQL: apply on empty db, roll back to empty, re-apply, idempotent second run, concurrent start.
2. Initial migration `0001`: users, email_tokens, user_preferences, devices, credentials, tags, user_revisions, processed_commands, with constraints (case-insensitive unique email via citext or lower() index, password-or-google check, partial unique tag name key among non-deleted, leisure-only distraction class check, single-use tokens, FKs with cascade for account deletion). Constraint tests for every invariant.
3. Wire into Nest (`DatabaseModule`, Kysely instance, typed table interfaces), boot runs migrations; `/health` stays a stub (T1.2). Update `docs/DEVELOPMENT.md`, ARCHITECTURE and seed README as needed.

### Interfaces
- `apps/server/src/platform/database/`: `DatabaseModule` exporting a `Kysely<Database>` provider; `migrations/NNNN-name.sql` (or up/down pair) with a runner `migrate(db, 'up' | 'down')`.
- Table/column names snake_case; ids stored as `uuid`; instants as `timestamptz`.

### Review focus
- Rollback on an empty database leaves zero tables (including the migration table policy: state it).
- Case-insensitive email uniqueness; tag unique among non-deleted only; one preferences row per user; credential family revocation queryable by family id.
- Concurrent server starts must not double-apply.
- No raw tokens or secrets in any column.
