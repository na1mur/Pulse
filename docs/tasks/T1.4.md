- From T1.2: config already validates `SMTP_HOST`, `SMTP_PORT` (default smtp.gmail.com:465), `SMTP_USER`+`SMTP_APP_PASSWORD` all-or-nothing, `MAIL_FROM`, `PUBLIC_API_URL`; the dev environment uses Mailpit (`SMTP_HOST=localhost`, `SMTP_PORT=1025`, no auth, no TLS; `pnpm dev:up` prints them, dev stack on this machine is on 11025 / inbox 8025). OPS-04: logs carry request IDs and user IDs only, so never log recipient addresses, links, tokens or message bodies. Links in emails are built from `PUBLIC_API_URL` and a token; the token itself is created by T1.5/T1.7 (this task takes it as an input).
- Module layout: `apps/server/src/mail/` (ARCHITECTURE section 3): transport + templates, used by auth later. Controllers never touch it; a `MailService` with one method per email type taking typed inputs (to, token/link, locale-free), returning a result (`sent` / `failed` with a safe reason) so the caller can report; a failed send is logged (class/code only, user ID if available) and surfaced, never swallowed. Plain-text plus simple HTML, no remote images, escape all interpolated values.
- Acceptance checks by the builder: integration test against the dev Mailpit (or an in-process SMTP test server, preferably, so tests need no extra service; if you use Mailpit, skip with a clear message like the database tests) that every template arrives with the right subject/copy, link and text/HTML parts; a failing SMTP server gives a `failed` result, a log line without address/body, and no throw into the caller's transaction; header-injection attempts in the address are rejected; disabled-mail configuration (no SMTP configured) is reported, not silent.
