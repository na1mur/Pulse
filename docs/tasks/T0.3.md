No user stories are cited. Context:

- Spec section 11, "CI / release" row and D-28 (decided 2026-10-25 by the owner): GitHub Actions; a repository ruleset on `main` requires a pull request with the `ci` check green and forbids force-push and deletion; the repository admin may bypass it so `auto-commit` commits can still be pushed straight to `main`, where CI runs again.
- ADR-0001: no task runner; CI runs the toolchains as separate jobs.
- `docs/ARCHITECTURE.md` section 5: dependency-cruiser and the ESLint network rule run in `pnpm verify` and CI.
- `scripts/check.mjs` (T0.2) is the one definition of the checks: groups `docs`, `ts`, `rust`, `android`. The `rust` group builds `apps/desktop/dist` itself when `ts` is not in the same run (the Tauri crate embeds it), so it needs a pnpm install.
- `docs/operations/secrets-and-signing.md` "CI" rule: secrets only as Actions secrets, only in release jobs; forks get none; never `pull_request_target` with a checkout of PR code. T0.3 needs no secrets.
- `docs/AGENTIC_SETUP.md` A6.1 (CI): this task covers lint, type check, tests and builds; the server image build arrives with its Dockerfile in T1.3, the Windows installer, signed APK and size budgets in T0.7.
- Deferred to this task from T0.2: the checkout needs `fetch-depth: 0` for `scripts/check-docs.sh`.
- Toolchain pins: Node `.node-version` (24.15.0) with pnpm from `packageManager` (Corepack), Rust `rust-toolchain.toml` (1.97.0, Windows target only until T0.7), JDK 17 and Gradle through the wrapper.
- Repository: `na1mur/Pulse` on GitHub, public, default branch `main`.

**Out of scope:** the server image (T1.3), installers, signing, release jobs and size budgets (T0.7), E2E suites (T7.8), Dependabot/Renovate and other dependency hygiene (A6), the T0.2 review notes on `check.mjs` internals.

## Plan

### Slices

1. **CI workflow and ruleset definition** - devops-engineer - `actionlint` on the workflow; Prettier passes on the YAML; each job's command run locally where the OS allows (`node scripts/check.mjs --only <group>`); the ruleset JSON validated against the GitHub REST schema by inspection.
2. **GitHub side** - lead (owner approved 2026-10-25) - push branch `t0.3-ci`, open a PR, watch the run go green; apply the ruleset with `gh api`; prove a red PR is blocked with a throwaway PR (deliberate failure), then close it and delete its branch.
3. **Docs** - devops-engineer (with slice 1) - `CLAUDE.md` Commands (CI line), `docs/AGENTIC_SETUP.md` A6.1 (partial: server image T1.3, installers and size budgets T0.7), `docs/operations/secrets-and-signing.md` (CI uses no secrets yet), `docs/knowledge/INDEX.md` entry for where CI and the ruleset live.

### Interfaces

- `.github/workflows/ci.yml`, workflow name `CI`. Triggers: `pull_request` (any base branch), `push` to `main`, `workflow_dispatch`. Top-level `permissions: contents: read`; `concurrency` per workflow and ref, cancelling superseded PR runs only. Every third-party action pinned by full commit SHA with a `# vX.Y.Z` comment. Each job has `timeout-minutes`.
- Jobs, each running exactly `node scripts/check.mjs --only <group>` after setup, so CI and `pnpm verify` cannot drift:
  - `docs` on `ubuntu-latest`: checkout with `fetch-depth: 0`; Node from `.node-version`; no install (the group needs none). Also runs `actionlint` (pinned version) on `.github/workflows/`.
  - `ts` on `ubuntu-latest`: Node from `.node-version`, pnpm through Corepack, pnpm store cache, `pnpm install --frozen-lockfile`.
  - `rust` on `windows-latest` (the Tauri crate is Windows-only): Node + pnpm + frozen install (for the desktop UI build), toolchain from `rust-toolchain.toml`, Cargo cache keyed on `Cargo.lock` and the toolchain.
  - `android` on `ubuntu-latest`: JDK 17 (Temurin), Gradle cache via the official Gradle setup action (wrapper validation on), the runner's preinstalled Android SDK through `ANDROID_HOME`.
  - `ci` on `ubuntu-latest`: `needs` all four, `if: always()`, fails unless every needed job succeeded. This is the only required check name.
- `.github/rulesets/main.json`: the ruleset body for `POST /repos/{owner}/{repo}/rulesets`: name `main`, target `branch`, enforcement `active`, include `~DEFAULT_BRANCH`; rules `deletion`, `non_fast_forward`, `pull_request` (0 approvals), `required_status_checks` with context `ci` (integration GitHub Actions, id 15368); bypass actor the repository admin role (`RepositoryRole`, id 5, `bypass_mode: always`). Applied by the lead in slice 2, kept in the repo so it can be re-applied.

### Review focus

- CI must run the same commands as `pnpm verify` (no second definition of the checks).
- Supply chain: SHA-pinned actions, read-only token, no secrets, no `pull_request_target`.
- Fresh-runner reproducibility: frozen lockfile, `--locked` Cargo, Gradle wrapper validation, toolchains taken from the repo's pin files rather than the runner's defaults.
- The `ci` aggregate must fail when any job fails, is cancelled or is skipped (a skipped dependency must not make `ci` green).
- The ruleset must not lock the owner out of pushing to `main` (bypass) and must block a red PR.
